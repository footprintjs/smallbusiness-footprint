# Diagnostic boundaries

Repository guide. `../diagnostics.ts` normalizes bounded provider-shaped errors and exports optional wording. `runtime.ts` explicitly wraps Blueprint's real call recorder. `explanations/` owns immutable problem/suggestion presets, not a second diagnosis engine.

The unreleased `aftersalesCause.ts` entry projects actual saved native after-sales scope histories and delegates queries to the public canonical reader. It preserves sparse stage reads and original per-write prefixes, marks missing/cross-scope evidence incomplete, and refuses inconsistent run/scope/control/fact ownership. It does not flatten a native snapshot to satisfy a root-only generic diagnosis parser. See [the exact reader and limits](../../docs/AFTERSALES-CAUSE.md).

Attach the recorder at the actual database/payment/shipping call before a host wrapper loses safe classification. Keep logical calls, physically observed attempts, domain receipts and persistence outcomes separate. No observed callback means unknown coverage, not zero provider attempts. No description, HTTP status or SDK class proves an upstream outage.

Use [provider evidence](../../docs/PROVIDER-EVIDENCE.md) and [expected evidence](../../docs/EXPECTED-EVIDENCE.md). Target tests in `src/__tests__/testing/` and `src/diagnostics/explanations/__tests__/`. Never persist raw provider errors, private payloads or test counters as diagnosis evidence.

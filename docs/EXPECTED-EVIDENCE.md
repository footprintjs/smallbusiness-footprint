# Expected commerce work and missing evidence

Use `footprint-blueprint/diagnostics/coverage` beside the existing cause reader. Both use the shared Foottrace record and requirement contracts; coverage does not create causal nodes or replace the cause walker.

The host supplies a trusted, bounded declaration of the expected stage IDs for the exact run and scope. Supply descriptions from application code, never from customer text or arbitrary saved trace prose. Inspect only an authorized record. Descriptions are context, not proof.

A saved commit establishes that execution was observed. It does not prove a refund settled, stock was restored, or a shipment was delivered. A declared step absent from retained commits is **not observed**, with an unresolved evidence requirement. It is not automatically skipped, failed or unreachable. A missing declaration means the expected inventory is unknown; a partial declaration cannot certify the whole flow.

Branch, loop and nested-flow coverage needs actual stable scope bindings and retained decision evidence. A display name, correlation ID or an earlier failure does not prove why another step is absent. Keep unavailable scopes and incomplete prefixes explicit. Old records do not gain missing evidence retroactively.

The expected-work inventory stays separate from the actual cause graph. Preserve unknown payment or refund outcomes and use the existing provider reconciliation workflow. The optional investigator may explain recorded findings and gaps, but cannot fill those gaps by guessing or approve a financial action.

The Charming Cherubs host adds safe descriptions and renders this separate coverage panel in its admin view. Other brands supply their own descriptions, policies, storage and provider adapters. No model is needed for coverage classification.
